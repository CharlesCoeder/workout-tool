# Decisions log

Sensible calls made without asking, newest last.

1. **RTDB for history too, not Firestore.** One SDK module, one rules file, one mental model. Volume is tiny.
2. **Household id as capability, not per-UID data.** Anonymous auth gives each device a different UID, so TV and phone can't share a UID-scoped tree. An unguessable 20-char household id under rules that require any signed-in user is the simplest safe-enough model for one person's workout log.
3. **Local mode by default.** With no Firebase env the app runs fully in one browser (localStorage + BroadcastChannel). You can try everything before creating a Firebase project.
4. **Timers are timestamps; transitions are derived.** No client owns a countdown. `settle(state, now)` is pure and both screens agree.
5. **One tap per set.** The rep picker is shown during the set; tapping a number ends the set and starts the rest. A separate "Done" then "how many?" path exists for voice.
6. **Rest before a new exercise doubles as "get ready".** A separate ready screen before every exercise would add dead time. The rest screen shows next exercise, weight, plate change and demo, and is extended by a re-rack bonus when plates change.
7. **No automatic deload.** The program doesn't specify one. If you fall short of the range the weight stays; you can override on the remote.
8. **Starting weights are guesses.** Each exercise has `startWeightLb` in settings; the remote's override snaps to your plates so a wrong guess costs one tap.
9. **Substitutions are planned on the phone.** The remote computes the substitute's weight/loading from history and inventory and sends a complete planned exercise in the action, keeping the reducer free of history/inventory.
10. **History is upserted after every logged set.** An abandoned session still counts for progression.
11. **Single-dumbbell lifts and the second handle.** The TV shows the loading for the working handle and says "strip the other handle" only when the plate pool requires it.
12. **Demo videos are YouTube embeds by default**, looping, with sound, with a "no demo yet" card when an exercise has none. Recording your own means pasting a URL in settings. Browsers refuse sound until the page has had a gesture, so every player starts muted and is unmuted after the TV's first click (the same click the beeps need); the phone has a sound toggle that persists like speed. When the enlarged stage and the side player are both mounted, only the stage carries sound.
13. **No router library, no CSS framework, no state library.** Four pages, hand-rolled path switch, CSS custom properties. Dependencies: react, react-dom, firebase.
14. **Demo clips are public YouTube tutorials**, chosen by search and checked for embeddability. Several are Muscle & Strength's own demo videos; the site itself blocks scraping so IDs were found via search. The `loop` embed parameter restarts from 0, so the per-exercise "start at" offset only applies to the first play.
15. **Countdown beeps need one click on the TV page.** Browsers block audio until a user gesture; the TV shows a one-line hint until it has one. Casting a tab from a laptop counts as the laptop's click.
16. **Voice runs only while a session is live** and restarts itself whenever Chrome ends the recognition stream. Numbers are accepted only during a set (or after "done"), so a stray "ten" mid-rest does nothing.
17. **Rest after the last set of an exercise uses that exercise's rest**, plus the re-rack bonus when plates change. The rest before the first exercise is the "get ready" countdown instead.
18. **Firebase is split into its own chunk** so the app shell stays small; the SDK is only loaded when env vars are set.
19. **Pausing dims nothing.** The paused state is a small badge in the corner; the countdown just stops. The demo keeps playing so you can study it.
20. **The enlarged demo is a stage, not a flash.** "Demo video" on the phone puts the clip full-screen on the TV with the timer (or "Paused") in the corner, and it stays until you hide it or the set starts. The phone drives the player through the YouTube IFrame API: restart, ±5 s, play/pause, a scrubber, sound on/off, and 0.25×–2× speed. Speed and sound persist across exercises until changed.
21. **The scrubber is driven by a small feed from the TV, not by guessing.** The TV writes `demoPlayback` (position, duration, playing, rate, sampled-at) beside `live`, only when something the phone can't extrapolate changes (seek, pause, loop, rate) plus a 5 s heartbeat; the phone extrapolates the playhead from the sampled-at timestamp on the shared server clock. It is a separate node so the TV's writes never race the phone's whole-state writes to `live`. The play/pause icon comes from the same feed, with a few seconds of optimistic state after a tap so the button answers instantly. If the feed goes stale (TV tab closed), the scrubber greys out rather than drifting.
22. **Mistakes are corrected in place, not by deleting sessions.** A wrong tap on the rep grid is the most common error, so "Undo" sits right under the rest countdown, and "Logged sets & notes" (under More, and on the summary) lets you retype any set and add a note per exercise or per session. Undo takes back the most recently logged set wherever it was, puts you back on it, un-skips the exercise and even re-opens a finished session; the history record follows every correction, and disappears if the only set is taken back. Notes are written when you leave the field, not per keystroke, because every write is the whole live state.
23. **Records are derived, never stored.** PRs, estimated 1RM (Epley) and volume are recomputed from history every time, so edits and deletions can't leave a stale trophy behind. A set gets at most one label, in the order that matters most for double progression: heaviest weight, then most reps at this weight, then "strongest by estimate" for a never-used lighter weight. Nothing counts the first time an exercise is done, and a set is compared against earlier sets of the same session too, so a session yields the PRs it actually set rather than three badges for the same milestone.
24. **"Aim for N" follows the logbook, not a formula.** The target for a set is one more rep than the same set last time at this weight, capped at the top of the range; at a new weight it is the bottom of the range; at the plate ceiling it is the top again. It is shown on the TV during the set, in the rest card for the next set, and as a ringed number on the phone's rep grid. No RPE, no percentages.
25. **Progression rule is a setting; stalls are advice, not automation.** The program's rule (first set at the top of the range) stays the default; "every set" is offered for anyone who wants the stricter, slower version. A stall is counted only when a session fails to beat the one before it (first-set reps or total reps) at the same weight, so climbing the rep range never reads as being stuck. After three such sessions the TV's get-ready screen says so and suggests one step down for a session; the weight is never changed automatically (see decision 7).
26. **History leads with adherence, not lifts.** For someone starting out, sessions per week predicts results far better than any single lift, so the History page opens on an Overview: this week's days, a 12-week grid with weekly counts (green when the target is met), pounds moved per week, sets per muscle against what the program prescribes, and the latest records. Weeks start on Monday in local time. No streaks: a missed week is a blank column, not a broken chain.
27. **Muscle balance counts sets, with a half credit for secondary muscles.** Each exercise lists the muscles it works, main first. A set counts 1 for the main muscle and ½ for the others, which is how most weekly-volume guidance is applied. The chart shows this week's sets over the program's weekly prescription so an unbalanced program (or a skipped day) is visible at a glance. The guidance quoted (10–20 hard sets per muscle per week, ~10 for a beginner) is the common range from the hypertrophy literature.
28. **Est. 1RM as a second lens on the lift charts.** Weight-per-session charts are stairs; the Epley estimate of the best set gives a smoother line that moves when reps move. It is a toggle, not the default, and is labelled as an estimate.
29. **CSV export, one row per set.** The JSON backup is for restoring; the CSV is for a spreadsheet. Volume is included per row so charts can be rebuilt without knowing the pair/per-side rules.
30. **A session idle for three hours is offered for discarding, not resumed.** Closing the app mid-workout used to leave the TV on "Go" and the phone in the middle of a set the next day. Now the phone shows a card with what was logged and two choices; "Discard" keeps whatever sets were done (they still count) and clears the screen. The TV only hints at it, because the TV has no buttons.
31. **Day cards say how long a day takes.** The median of the last five completed sessions of that day when there are any, otherwise an estimate from sets, rests, warm-up and plate changes (about three seconds a rep plus setup). "Do I have 40 minutes?" is the question that decides whether a session happens.
32. **Plate forecasts say "weeks" and "months", never dates.** History → Plates lists each lift's current weight, ceiling and steps left, with two horizons: "at your pace" (steps actually gained per session × how often the lift comes round, from the last eight weeks) and "at best" (a step every session, the most the rule allows). With a four-rung pair ladder the honest answer is often "next session", which is the point: it tells you to order plates before you are stuck, not after.
33. **The upgrade simulator reuses the plate engine, not a lookup table.** Tapping "4 × 10 lb" merges plates into a copy of the inventory and recomputes the ladders, so the effect on ceilings, on which stuck lifts get room, and on the size of each jump is exact for this set. The biggest-jump figure ignores the step off the empty handle, since nobody trains at 4 lb. Nothing is bought or saved from that screen; equipment stays in Settings.
34. **Body weight is a trend, not a number.** Readings are stored one per local day under `bodyweight/{YYYY-MM-DD}` and smoothed with an exponential trend (α = 0.1 per day, about a ten-day memory, the usual choice in scale-trend apps); gaps advance the smoothing as elapsed days so a reading after a week away moves the line more than one the next morning. The weekly rate is a least-squares slope of the trend over the last three weeks and is withheld until there are at least four readings spanning ten days, because two mornings can't tell you anything. The phone's home screen carries a one-tap weigh-in since that is where the morning starts.
35. **Nutrition is targets and a nudge, not a food diary.** A profile (sex, birth year, height, activity, goal, pace) plus the body-weight trend gives Mifflin-St Jeor resting energy × an activity factor, ±500 kcal/day per pound a week, protein at 0.7–1 g/lb (top of the range while losing), fat at 25–35% of calories, carbs as the remainder, with a floor at resting energy and never below 1,200/1,500 kcal. What makes it more than a calculator is the adjustment: once the trend has three weeks of readings, its weekly rate is compared with the plan and a change of at most 300 kcal is suggested, only when the gap is at least 100 kcal. There is deliberately no food database; logging meals is a different app and a different habit.
36. **The TV shows the whole day in one strip.** Under every screen sits a row of the day's exercises: done (ticked), current (highlighted, with sets done), still to come, skipped (struck through). "3 of 6" is a number; the strip is a picture of how much is left, which is what actually makes a session feel finite.
37. **The TV page takes keyboard input, quietly.** A laptop casting the tab has a keyboard right there, so Enter/Space start or skip, digits then Enter log reps (shown top-right while typing), P pauses, U undoes, D toggles the demo, + adds 30 s. The mapping is a pure function with tests; the hint appears only on the get-ready screen. The phone remains the primary control.
38. **The idle screen shows the plan with weights and a length.** Before a session starts the TV already shows what's coming, at what weight, with ▲ for lifts that stepped up, and "about N minutes". Knowing exactly what the next 40 minutes contain removes one more reason to put it off.
39. **The phone buzzes at 3-2-1 and go.** Same cues as the TV beeps, felt through the floor when the phone is face down. It is a setting, on by default, and does nothing on iPhones because Safari has no vibration API; the copy says so rather than pretending.
40. **One demo player per exercise, moved rather than re-created.** A YouTube iframe restarts the instant React unmounts it, so a player rendered inside each screen meant the clip jumped back to the start every time the rest screen became the set screen, and again when "Demo video" put it on the stage — with the audio restarting too. Now the screens render an empty `DemoSlot` saying *where* the clip belongs, and a single fixed-position player animates onto whichever slot is showing (`src/tv/DemoLayer.tsx`). Full screen is the same player growing: nothing reloads, nothing loses its place. The slot is measured rather than guessed, because the layout differs per screen and the TV can be any size.
41. **The clip comes off the screen when a set starts, paused where it was.** By the time you are lifting you have seen the movement; a video playing at you through a set is noise you cannot reach the controls of. So the player is parked, not unmounted, and not rewound: "Show on TV" (or the S key) brings it back at the same second, still at the same point in the clip. A setting keeps it up during sets for anyone who wants that. The corollary is that opening the demo controls on the phone no longer forces the clip onto the TV — asking for the controls is not asking for the video.
42. **Speed is a gesture, not a preference; sound, captions and loudness are preferences.** 2× is how you skim *this* clip, so a new exercise starts at normal speed again rather than quietly playing the next demo at double speed. Sound on/off and captions carry across exercises, because those are about the room you are in.
43. **Captions, at the cost of the overscan.** Clips are watched at speed with a TV's distance and a fan running, so a word you missed should be readable rather than re-wound to. The YouTube embed is overscanned by 18% to hide its chrome, which is exactly where subtitles sit, so with captions on the frame is shown at its true size and a little YouTube chrome comes back. That trade is only paid while captions are on.
44. **Loudness is a property of the clip, stored per exercise.** Demo clips are mastered at wildly different levels, and the fix is not to ride the TV volume all session: set a level once from the phone while it plays, and that exercise starts there every time after. Clips with no level of their own use one setting for all of them.
45. **A set records the weight it was done at.** Dropping the weight for the last set is normal training, but the record only kept the exercise's working weight, so the change vanished from history and from every number derived from it. `weights` is now written per set when they differ (older records and even sets cost nothing), and volume, PRs, records and the CSV all read per set. Progression still reads the first set, so backing off late never costs you the step — and the sheet that lets you correct it says so.
46. **No "overridden" badge.** Changing the weight is a thing you did on purpose ten seconds ago; a badge for it reads like a warning light and implies you left the program. The prescribed weight still appears where it is useful — quietly on the TV, and as "Prescribed: N lb" in the sheet where you pick a weight.
47. **Rest moves in both directions.** "+30 s" without a "−30 s" says the app's guess outranks how you actually feel. `extendRest` takes negative seconds, clamped so the countdown never goes below zero, and landing on zero starts the set exactly as waiting it out would. The phone shows −30/−5/+5/+30 in one row; the keyboard has − alongside +.
48. **Sheets keep their header and freeze the page behind them.** The close button used to scroll away at the top of a long list of sets, and a flick that began in a text field scrolled the session screen *under* the sheet instead of the sheet itself. The panel is now a fixed header over a scrolling body with `overscroll-behavior: contain`, the page behind is pinned while a sheet is open (and its scroll position restored after), and touching anything that is not a field gives up the caret. Notes save themselves shortly after you stop typing, and the header says whether that has happened, because "did my note save?" should never be a question you close a sheet to answer.
49. **The screen is kept awake on every page, not just during a session.** Nobody should have to change their phone's display timeout to use a workout app, and the old lock only covered a running session on the remote. It is now requested app-wide, on by default, with a setting to turn it off; Settings reports whether the browser actually granted it rather than claiming the screen will stay on. The lock is dropped whenever the tab is hidden, so it is re-taken on every return and on the first tap if the browser wanted a gesture.
50. **Gear you own is part of the inventory; swaps are offered, never applied.** The seed program presses off the floor because it assumes a floor, and the app had no way to know about a bench. Equipment now lists a bench, a step and a pull-up bar, exercises declare what they need, and the library gained the bench press and incline press. Owning a bench turns into a one-line offer on the get-ready screen and a sorted swap list — not a rewritten program, which stays the rule for anything that changes what you will do (see DIRECTION). The swap sheet can make a swap permanent, because "every session from now on" is a choice you should be able to make in the moment you notice.
51. **The rep grid says what extra reps are worth.** Numbers past the top of the range looked exactly like the target, which reads as an invitation to chase them, and under the program's rule they earn nothing: the first set reaching the top is the whole trigger, and reps beyond it are energy spent on a number nothing will read. Those numbers are still there and still tappable — you did them, so log them — but they are drawn quietly, and a line says why, including the two cases where extra reps *are* the progress: at the plate ceiling and on bodyweight work. The first set of a new exercise also explains what a range is for: 6–12 is a ladder you climb over sessions, not a choice between 6 and 12.
